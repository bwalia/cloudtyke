Azure landing zones, drawn out

An Azure landing zone is a ready-made environment for your apps. The Microsoft Cloud Adoption Framework (CAF) describes a reference design for it. The platform team builds identity, networking, security and governance once. Each app team then gets a subscription that already follows the rules.

This section explains that design with diagrams you can click. Start with the hierarchy, then read the topic pages, then walk through five scenarios: build new, migrate, upgrade an existing estate, modernise, and run a subscription's lifecycle.

Figure 0

A landing zone at a glance

Two kinds of landing zone. The platform landing zone holds the shared services: identity, management and the connectivity hub. Application landing zones hold the apps. Each one is a subscription, peered to the hub and covered by the same rules. Click any box.

Topics and scenarios

    What you can practise on CloudTyke

    Works in the emulator

    • A read-only management group tree from the seed: ct-platform, ct-landingzones, ct-sandbox, with sub-connectivity, sub-management and sub-sandbox
    • Azure Policy definitions, initiatives and assignments at management group scope, enforced on every write
    • Azure RBAC with inheritance, custom roles, Entra users, groups, managed identities and GitHub OIDC
    • Hub and spoke: VNets, subnets, peering, NSGs, route tables, private DNS zones, public IPs, and Virtual Network Manager hub-and-spoke
    • Log Analytics, Key Vault (secrets), Storage, Container Registry, AKS, PostgreSQL flexible server and Cosmos DB (control plane)

    Not in the emulator

    • Creating or moving management groups, and creating subscriptions (no subscription vending API)
    • Azure Firewall, Bastion, VPN and ExpressRoute gateways, Virtual WAN (no resources, no data path)
    • Microsoft Defender for Cloud, Microsoft Sentinel, Azure Update Manager, Backup and Site Recovery, Cost Management
    • Privileged Identity Management, MFA, Conditional Access, access reviews
    • App Service, Functions, Container Apps, Azure SQL, API Management, Service Bus, Azure OpenAI and others outside azure-emulator/docs/coverage.md

    Sources: azure-emulator/docs/coverage.md and azure-emulator/docs/known-gaps.md.

    Build it yourself: azure-emulator/examples/terraform/landing-zone/ creates a CAF-style platform with spokes. landing-zone-stadium/terraform builds the Arena's version.

    In the stadium

    The platform landing zone is the stadium you build once: gates, control room, safety code. Each application landing zone is an event space on the pitch. Vending is booking an event. See it as a picture in Chapter 1, Build the stadium.
